# Промпт для запуска Agent Team

Открой новую сессию Claude Code в директории проекта и вставь этот текст:

---

```
Проведи полный UX/UI аудит PeakTalk перед реализацией улучшений.

Контекст: реальный тестовый пользователь (руководитель обучения Газпром Медиа) тестировала приложение на телефоне и дала фидбек:
1. После онбординга — тупик, непонятно что делать дальше
2. Мобильный лендинг сломан — бургер-меню не работает, вёрстка разъезжается
3. Дашборд «визуально мёртвый» — скучные карточки без жизни и мотивации
4. Навигация между разделами неочевидна — из дашборда к действию путь неясен
5. Нет выбора сложности при настройке симуляции
6. Нет голосового ввода в чате — неудобно набирать большие ответы на телефоне

Ограничения:
- Мобильный — ГЛАВНЫЙ приоритет (основная аудитория на телефонах)
- Палитру, шрифты, стек НЕ менять — полируем то, что есть
- Голосовой ввод: Web Speech API (браузерный, локальный)
- Бэкенд не переписываем

Создай команду агентов из 4 тиммейтов:

1. **UX Researcher** — анализирует все user flows от регистрации до отчёта. Находит тупики, точки потери пользователя, проблемы с навигацией, empty states без CTA. Особый фокус на first-time experience после онбординга. Записывает все находки в audit/01-ux-research.md.

2. **UI Designer** — визуальный аудит каждой страницы дашборда. Главный фокус: как оживить «мёртвый» дашборд — прогресс-визуализация, мотивирующие элементы, персонализация, дизайн empty states. Оценивает визуальную консистентность. Записывает в audit/02-ui-design.md.

3. **Whimsy Injector** — добавляет personality и душу продукту. PeakTalk — это AI-тренер, он должен мотивировать. Предлагает tone of voice для UI-текстов, микро-анимации (Framer Motion уже подключён), delight-моменты (завершение симуляции, хороший результат), лёгкую геймификацию (стрики, прогресс). Записывает в audit/03-whimsy.md.

4. **Accessibility Auditor** — полный мобильный аудит. Находит баг бургер-меню на лендинге, проверяет touch targets (≥44px), размеры шрифтов (≥16px для предотвращения iOS auto-zoom), горизонтальный overflow, чат симуляции с виртуальной клавиатурой. Записывает в audit/04-accessibility-mobile.md.

Каждый тиммейт должен ЧИТАТЬ реальный код каждой страницы и компонента, а не гадать. Агенты НЕ пишут код — только анализируют и дают конкретные рекомендации с указанием файлов.

После завершения всех 4 аудитов — создай консолидированный план audit/05-consolidated-plan.md с приоритизированным backlog (Critical → Low), группировкой по файлам и порядком реализации.
```
