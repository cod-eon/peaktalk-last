# Dashboard UX Audit & Improvement Plan

## Context

Текущий дашборд (`/dashboard`) — это **статичная заглушка**. Страница не делает ни одного API-вызова. Все метрики показывают "--", график — пустышка с хардкодированными датами, лента симуляций — пустое состояние. Новый пользователь после онбординга попадает на стену прочерков, не понимает что делать и теряет мотивацию. Для пользователей с реальными данными ситуация ещё хуже: их прогресс просто не отображается.

**Цель**: Превратить дашборд в рабочий командный центр, который различает нового и активного пользователя, показывает реальные данные и направляет к действию.

---

## Stage 1 — Data Layer + Разделение на пустой/активный стейт

**Самый большой импакт. Без этого всё остальное не имеет смысла.**

### 1.1 Создать хук `useDashboardData`

**Создать:** `frontend/src/hooks/useDashboardData.ts`

- Параллельно вызывает `GET /me`, `GET /simulation?limit=10`, `GET /documents?limit=10` через `Promise.allSettled`
- Переиспользует `useBilling()` для данных плана/лимитов
- Вычисляет `userState: 'loading' | 'new' | 'active'`:
  - `new` = 0 сессий И 0 документов
  - `active` = есть хотя бы одно из двух
- Экспортирует: `{ profile, sessions, documents, billing, userState, isLoading }`
- Паттерн: `useEffect` + `api.get()` + локальный стейт (как на странице симуляций), не вводить TanStack Query здесь

### 1.2 Рефакторинг `DashboardPage` — условный рендер

**Изменить:** `frontend/src/app/(dashboard)/dashboard/page.tsx`

- Добавить loading-скелетон (pulse-бары neutral-100, animate-pulse, rounded-none)
- `userState === 'new'` → компонент `DashboardNewUser`
- `userState === 'active'` → компонент `DashboardActive`

### 1.3 Пустой стейт для новичка (`DashboardNewUser`)

**Убрать**: стену пустых метрик "--", пустой график, пустую ленту.

**Показать:**
- Персонализированный заголовок по данным онбординга (segment → конкретный текст):
  - `manager` → "Подготовьтесь к защите решений"
  - `founder` → "Отрепетируйте инвест-спич"
  - `head` → "Подготовьтесь к бюджетной защите"
  - `customer_facing` → "Подготовьтесь к QBR"
  - `other` → "Начните первую симуляцию"
- Два CTA-блока (как на шаге 3 онбординга): "Загрузить документ" (outline) + "Начать симуляцию" (primary чёрная)
- Краткое пояснение: "Загрузите текст выступления или начните тренировку с ИИ-оппонентом"
- `PlanBadge` (из `frontend/src/components/PlanBadge.tsx`) + остаток симуляций из `useBilling().simulationsLeft`
- **Никаких пустых метрик, никакого пустого графика**

### 1.4 Активный стейт с реальными данными (`DashboardActive`)

Сохраняем структуру (header → метрики → контент), но с настоящими числами:

- **ИНДЕКС УСТОЙЧИВОСТИ**: средний `avg_score * 10` по завершённым сессиям. emerald >= 7, amber >= 4, red < 4
- **КРИТИЧЕСКИЕ УЯЗВИМОСТИ**: кол-во сессий с `avg_score < 0.4`
- **СЕССИЙ ЗА МЕСЯЦ** (заменяет "УРОВЕНЬ ВОДЫ" — согласовано): количество симуляций за текущий месяц. Иконка: `BarChart2` или `Activity`, цвет amber. Вычисление: фильтр сессий по `created_at >= первый день текущего месяца`.
- Если все `avg_score === null` — показать "--" с подписью "Завершите симуляцию для расчёта"

## Stage 2 — Лента сессий + Quick Resume

### 2.1 Лента последних сессий

Заменяем пустую секцию "ЛЕНТА СИМУЛЯЦИЙ" реальными данными (до 5 последних):
- Карточка сессии: персона (иконка + лейбл), индустрия, дата, оценка X/10, статус
- Клик: completed → `/simulation/{id}/report`, active → `/simulation/{id}`
- Пустой стейт остаётся для нового пользователя (но он уже на `DashboardNewUser`)

### 2.2 Баннер "Незавершённая симуляция"

Если есть сессия со `status === 'active'`:
- Показать промо-баннер над метриками: `border-2 border-neutral-900 bg-neutral-50 p-4`
- "У вас есть незавершённая симуляция" + имя персоны + кнопка "Продолжить"

### 2.3 Вынести общие константы персон

**Создать:** `frontend/src/lib/constants/personas.ts`

Перенести из `simulation/page.tsx`:
- `PERSONA_LABELS`, `ROLE_VISUALS`, `SHORT_PERSONA`, `formatDate`, `getInsightTag`

**Изменить:** `frontend/src/app/(dashboard)/simulation/page.tsx` — импорт из нового файла

## Stage 3 — График + Секция документов

### 3.1 Замена фейкового графика

**При >= 3 завершённых сессиях**: простой SVG line chart (без библиотек):
- Точки: `avg_score * 10` по оси Y, `completed_at` по оси X
- Пунктирная baseline на отметке 5
- Цвет линии: emerald

**При < 3 сессиях**: панель "СЛЕДУЮЩИЕ ШАГИ" с контекстными подсказками:
- 0 документов → "Загрузите текст выступления для точной симуляции"
- 0 завершённых → "Завершите симуляцию для отслеживания прогресса"
- Нет активности > 7 дней → "Регулярная практика улучшает результаты"

### 3.2 Блок "Последние документы"

Компактная секция после ленты сессий (до 3 документов):
- Название (truncate) + дата загрузки
- Быстрое действие: "Начать симуляцию" → `/simulation?doc={id}`

## Stage 4 — Анимации + Mobile + Polish

### 4.1 Framer Motion анимации

- Метрики: stagger `initial={{ opacity: 0, y: 8 }}`, `delay: index * 0.08`
- Карточки ленты: аналогичный stagger
- `AnimatePresence` для перехода new → active

### 4.2 Mobile

- Проверить stacking на мобилке (метрики уже `grid-cols-1 md:grid-cols-3`)
- Quick-resume баннер не должен перекрывать MobileNav
- Учесть `pb-16` (пространство для нижнего навбара)

### 4.3 Скелетоны загрузки

- 3 прямоугольника в сетке метрик (neutral-100 animate-pulse)
- 3 полоски в зоне ленты
- 1 прямоугольник в зоне графика

### 4.4 Error fallback

- Если API-запросы упали → показать `DashboardNewUser` как fallback + toast "Не удалось загрузить данные"

## Архитектурные решения

| Решение | Обоснование |
|---------|-------------|
| Client-side вычисление метрик | Не нужен новый backend endpoint — берём 10 последних сессий и считаем на клиенте (как на странице симуляций) |
| Custom hook, не Zustand store | Данные page-scoped, не нужны другим страницам. Billing уже в store и переиспользуется |
| Shared persona constants | 60+ строк дублирования между dashboard и simulation page — выносим один раз |
| Никакой геймификации | Правило продукта: B2B-метрики — readiness score, уязвимости, активность |

## Проверка

- [ ] Новый пользователь (0 сессий, 0 документов): видит персонализированный empty state с CTA, без пустых метрик
- [ ] Активный пользователь: видит реальные метрики, ленту сессий, график (или подсказки)
- [ ] Активная сессия: баннер "Продолжить" появляется
- [ ] Mobile: всё читабельно, не перекрывает MobileNav
- [ ] API-ошибка: graceful fallback с toast
- [ ] Loading: скелетоны отображаются
