# ТЗ для Агента: Трансформация PeakTalk в Aura Workspace

**Дата формирования ТЗ:** 2026-06-29
**Основа:** `docs/research/aura-workspace-product-model-2026-06-29.md`, `docs/logto-migration-gate-2026-06-16.md`, а также текущий контекст и правила PeakTalk.

---

## 1. Контекст и Общая Цель
Текущий продукт (PeakTalk) сфокусирован на IT-специалистах и продуктовых защитах через механику текстовой симуляции.
**Новая цель (Aura Workspace):** Расширение на нетехнических профессионалов (HR, Event, Карьера, Менеджмент). Продукт становится AI-средой подготовки, где из сырого материала (текст/документ) генерируется целое *Дерево Артефактов* (анализ слабых мест, улучшенная речь, презентация, тайминг, шпаргалка) с обязательной финальной симуляцией оппонента (краш-тест).

Ключевой сдвиг в UX: от диалогового интерфейса "чат-бота" к контекстному рабочему пространству (Source-to-System Tree).

---

## 2. Разграничение Суб-Агентов (Sub-Agent Boundaries)

Трансформация масштабная, поэтому архитектурно она должна выполняться несколькими специализированными суб-агентами (или в рамках изолированных сессий/треков). Каждому суб-агенту делегируется своя зона.

### 2.1. Auth & Security Agent (Миграция Авторизации)
* **Контекст:** В логах обсуждался переход на локальную авторизацию. Был рассмотрен Keycloak, но выбран **Logto** как более легковесный и оптимизированный вариант для текущего стека (Next.js + FastAPI).
* **Задачи:**
  1. Заменить Supabase Auth на Logto OSS.
  2. Внедрить `@logto/next` в Next.js (App Router), перейти на redirect-based flow (отказ от собственных форм паролей).
  3. Настроить FastAPI зависимость (dependency) для валидации JWT токенов от Logto (по JWKS).
  4. Обновить схему БД (PostgreSQL / Alembic): вместо жесткой привязки к `users.id` как UUID от Supabase, создать поля `auth_provider` (на старте - 'logto') и `auth_subject`, сохранив `users.id` как локальный независимый UUID. Это важно для изоляции биллинга (YooKassa) и прогресса (Guest -> Paid).

### 2.2. Backend & Data Model Agent (Ядро и Структура Данных)
* **Задачи:**
  1. Разработать и применить миграции БД для хранения **Дерева Артефактов (Artifact Tree)**.
  2. Новая иерархия моделей: `Project` -> `Source Material` -> `Generated Artifacts` (Анализ, Спич, Выжимка, Презентация) -> `Simulations`.
  3. Реализовать версионирование: каждая правка материала пользователем через чат должна сохранять связь с исходным узлом.
  4. Подготовить REST API / GraphQL эндпоинты для фронтенда для навигации по дереву проекта.

### 2.3. AI Pipeline & Prompt Agent (Мозг Aura)
* **Задачи:**
  1. Разработать механику **Smart Upload**: анализ загруженного файла (PDF/DOCX) и генерация 3-7 *динамических вопросов* вместо запроса длинного ТЗ (например: "Кто аудитория?", "Есть ли риск-метрики?").
  2. Создать **Intent Engine**: роутер промптов для 5 базовых интентов: Event, Pitch, HR, Career, Academic.
  3. Сформировать пайплайны генерации артефактов (вызовы Gemini):
     - *Risk Map:* поиск логических дыр и нехватки цифр.
     - *Synthesis:* переписывание спича, составление выжимки и шпаргалки.
  4. Интегрировать старый симуляционный цикл PeakTalk (Simulation Loop) как финальный этап (краш-тест готового спича).

### 2.4. Frontend & UX Agent (Новый Интерфейс)
* **Задачи:**
  1. Изменить дизайн-систему со старой "темной" на "Smart, Calm, Agency-grade". Основные цвета: Background `#F6F8FB`, Primary Blue `#2563EB`, AI Accent Violet `#8B5CF6`.
  2. Реализовать дашборд и загрузку (Smart Upload Card), который плавно превращается в центральный узел графа (Source-node).
  3. Разработать главный UI-паттерн: **Artifact Tree**. Слева — дерево артефактов, в центре — Preview (Canvas) для чтения/редактирования, справа — контекстный AI-чат (Context Chat).
  4. Адаптировать интерфейс для Paywall (заблокированные узлы артефактов, которые стимулируют оплату после бесплатного базового анализа).

## 3. Обязательные Скиллы (Skills) для Агента
В начале выполнения задач будущий агент **обязан** использовать следующие проектные скиллы (из `AGENTS.md` и `.agents/skills`):
- `using-superpowers` — Глобальный скилл, определяющий строгий воркфлоу работы и обязательный вызов скиллов до генерации кода.
- `peaktalk-product-guard` — Должен применяться AI Pipeline Агентом для сверки новых фич с философией продукта (без геймификации, упор на high-stakes коммуникацию).
- `peaktalk-autonomous-dev-gate` — Должен применяться перед любыми масштабными коммитами и изменениями архитектуры (Auth и Backend).
- `peaktalk-ui-quality-gate` — Должен применяться Frontend Агентом для сверки с новой визуальной концепцией и кросс-браузерной проверки (desktop/mobile).
- `peaktalk-deploy-gate` — Обязателен при подготовке релиза и миграции базы данных.

## 4. Готовые Промпты для запуска Суб-Агентов

Для распределения задач в будущем, используйте эти готовые промпты для делегирования работы суб-агентам:

### 🚀 Промпт для Auth & Security Agent (Logto Migration)
```text
Ты — Auth Agent. Твоя задача — заменить Supabase Auth на легковесную альтернативу Logto в проекте PeakTalk.
1. Ознакомься с `docs/logto-migration-gate-2026-06-16.md`.
2. В бэкенде (FastAPI) настрой валидацию JWT от Logto JWKS-эндпоинта, замени старые проверки Supabase.
3. В схеме базы (Alembic) добавь поля `auth_provider` (по умолчанию 'logto') и `auth_subject`. Не заменяй локальный UUID (users.id) на внешний сабджект!
4. На фронтенде (Next.js) внедри `@logto/next`. Замени `supabase-js`, удали локальные страницы логина/пароля в пользу Logto Redirect Flow.
5. Защити существующие пути (`/billing`, `/upload`), убедись, что YooKassa продолжает работать с локальным UUID.
Обязательно используй скилл: peaktalk-autonomous-dev-gate.
```

### 🚀 Промпт для AI Pipeline Agent (Логика и Промпты)
