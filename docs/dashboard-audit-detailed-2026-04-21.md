## 1. Dashboard (`/dashboard`)

### Что работает хорошо
- Новая структура `DashboardNewUser`/`DashboardActive` четкая
- MetricPod компонент переиспользуем
- SimpleChart для динамики прост и эффективен
- Интеграция с PlanBadge корректна
- Активная сессия показывается с clear CTA

### Что работает плохо

#### 1.1 Несогласованность цветов в MetricPod
**Проблема:** Иконки в MetricPod используют захардкожженные цвета (`text-emerald-500`, `text-amber-500`, `text-red-500`), а функция `getScoreColor` использует другие оттенки (`#10b981`, `#fbbf24`, `#ef4444`).

**Код:** Строки 376-392 в `MetricPod`

**Риск:** Визуальный дисбаланс — иконки и текст могут не совпадать по тону.

**Рекомендуемый фикс:**
```typescript
// Использовать getScoreColor для иконок:
<Icon size={18} className={getScoreColor(avgScore).replace('#', 'text-')} />
```

**Приоритет:** P2

---

#### 1.2 DashboardDocuments показывает только 3 документа
**Проблема:** `recentDocs = documents.slice(0, 3)` — нет пагинации или "Показать все".

**Код:** Строка 186

**Риск:** Пользователь не видит все свои документы.

**Рекомендуемый фикс:** Добавить "Показать все" кнопку или пагинацию.

**Приоритет:** P2

---

#### 1.3 NextStepsPanel может быть перегружен информацией
**Проблема:** Логика определения советов сложная и может быть неочевидна пользователю.

**Код:** Строки 131-168

**Риск:** Пользователь может не понять, почему показан конкретный совет.

**Рекомендуемый фикс:** Добавить tooltip или объяснение для каждого состояния.

**Приоритет:** P2

## 3. Analysis (`/analysis/[id]`)

### Что работает хорошо

### Что работает плохо

**Проблема:** Импортируется `AnnotatePresence` вместо `AnimatePresence`.

**Код:** Строки 62-77

**Риск:** Аннотации не будут подсвечены.

**Рекомендуемый фикс:** Использовать fuzzy matching или нормализацию текста перед сравнением.

**Приоритет:** P2

---

#### 3.3 scoreTo10 не обрабатывает null/undefined
**Проблема:** Функция `scoreTo10` не проверяет входные данные на null/undefined.

**Код:** Строки 47-49

**Риск:** Может вернуть `NaN` при некорректных данных.

**Рекомендуемый фикс:** Добавить guard clause.

**Приоритет:** P2
